課後社團（ECA）自動化選課與動態名額管控系統
技術架構與衝突處理解決方案報告
一、 系統背景與痛點分析 (Problem Statement)
傳統學校使用 Google 表單進行選課時，常面臨三大核心痛點：
	1.	名額無法即時管控：表單無法在額滿時自動隱藏選項，導致大量超額報名，行政需人工協調抽籤或通知換課。
	2.	高併發搶課衝突（Race Condition）：多名學生在同一秒提交最後一個名額時，造成後台超額錄取。
	3.	人工維護成本高昂：各社團名額不一、需定時手動開啟/關閉表單、一人重複報名佔用多個名額，行政除錯負擔沉重。
二、 系統架構設計 (System Architecture)
本系統基於 Google Apps Script (V8 引擎) 開發，採 關注點分離（Separation of Concerns, SoC） 與 代碼優先（Code-First / IaC） 的現代化架構，將專案拆分為四大模組：

模組職責拆解：
	1.	Main.gs（調度層）：頂層指揮官，統一對外暴露 oneClickSetup() 達到「一鍵全自動部署」，並透過函式名稱後綴底線（_）隱藏底層私有實作，防範非技術人員誤觸。
	2.	Config.gs（參數層）：管理系統全域環境常數，包含表單識別碼、預設上限、開關表單時間戳記與通知信署名。
	3.	ECALimiter.gs（資料契約層）：以宣告式結構管理社團清單，社團物件支援 { name: "...", limit: 15 } 或 { name: "...", limit: "default" }，具備極高的動態擴展彈性。
	4.	Functions.gs（運算與基礎設施層）：封裝所有 Google Workspace API，負責併發排隊、時間解析、文字正則解析、動態 UI 渲染與郵件遞送。
三、 核心技術機制 (Core Technical Mechanisms)
1. 悲觀鎖併發控制（Pessimistic Locking via LockService）
⚬	技術原理：利用 LockService.getScriptLock() 在腳本進入點建立排隊機制，設定 15~20 秒的等待鎖（Wait Lock）。
⚬	作用：當尖峰時段百人同時送出表單時，系統強制將平行請求轉為序列化（Serialization） 處理，徹底消除資料讀寫時差造成的超額漏洞。
2. 動態標籤與正則回歸匹配（Dynamic Labeling & RegEx Parsing）
⚬	技術原理：為了提升前端填表體驗，系統在選項後方動態注入 [剩餘 X 名] 或 [最後 1 名!] 的提示。
⚬	技術難題：若選項文字動態改變，後台歷史資料會出現文字不一致問題。
⚬	解決方案：導入正則表達式 /\s*\[(剩餘|最後).*?\]$/i，在讀取回覆時即時將動態後綴剝離，還原純淨社團名稱比對，兼具「前端動態顯示」與「後端統計一致性」。
3. 容錯型時間字串解析引擎（Resilient DateTime Engine）
⚬	針對原生 JavaScript new Date() 於不同系統語系環境下解析 YYYY-MM-DD HH:mm:ss 易產生 Invalid Date 的缺陷，自研正則拆解分析器（Regex Time Parser），並結合台北標準時區（GMT+8），避免排程時差。
四、 關鍵邊界與衝突情境處理解決方案 (Edge Cases & Conflicts)
編號	衝突情境 (Edge Case)	潛在問題	系統解決方案與實作機制
01	同秒搶最後一個名額 (Race Condition)	兩人在同一秒載入與送出表單，表單底層同時接收兩筆回覆造成超額。	【時間戳排序 + 自動候補判定 + 專屬重選通知信】
1. 系統以毫秒級 Timestamp 嚴格排序。
2. 第 N 位判定為「錄取」，第 N+1 位判定為「候補」。
3. 系統自動抓取超額者 Email，利用 MailApp 發送通知信，並夾帶表單的 EditResponseUrl，指引學生直接回到未錄取的題目重新選擇。
02	一人重複提交表單 (Multiple Submissions)	學生反悔改選，多次填寫表單，在同一天霸佔多個社團名額。	【表單鎖定機制 + 最新有效原則 (Latest Wins)】
1. 表單前台開啟「僅限回覆 1 次」與「允許編輯回覆」。
2. 學生只能透過修改方式送出，後台永遠維持唯一資料。
3. 後台程式建立「舊名額自動釋出機制」：當學生由 A 社團改選 B 社團，A 社團人數即時 -1（若滿額將自動重新上架），B 社團人數 +1。
03	表單題名與設定不一致 (Human Typo)	人工建立表單容易發生空格、符號、大小寫微幅差異，導致比對失敗。	【代碼優先自動初始化 (Code-Driven UI Generation)】
表單日常只需保留固定題（姓名、年級），QuotaEngine 在執行時若偵測表單缺少該日題目，會調用 Form API 自動新增題目並注入說明與選項，徹底杜絕人為打錯字的風險。
04	執行時間超時限制 (GAS Execution Limit)	Google 觸發器有 30 秒執行限制，頻繁呼叫完整表單回覆可能逾時。	【記憶體快取與有效資料去重】
將選項上限陣列快取為 Key-Value Map，遍歷回覆時使用線性時間複雜度 O(N) 快速聚合，確保在短時間內完成鎖定與釋放。
五、 專案效益與管理優勢 (Business & Administrative Value)
	1.	極致的維護體驗（One-Click Setup）：
⚬	行政人員每學期只需在 Config.gs 設定時間、在 ECALimiter.gs 貼入社團名單，點擊一次 oneClickSetup() 即可完成上線，無需進入 GCP 或 Google Apps Script 鬧鐘介面手動設定 Trigger。
	2.	零超額風險與透明化名單：
⚬	透過悲觀鎖與時間序列分析，杜絕任何超額可能；即使同秒送出，候補順位亦有清晰時間證明，避免家長爭議。
	3.	行政作業自動化減少 90% 負擔：
⚬	釋放人工手動開關表單、核對名額、寄信通知重選的人工作業時間，全流程由系統背景非同步自動完成。
